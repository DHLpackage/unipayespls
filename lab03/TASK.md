# ЛР3. Два отправителя с одним интерфейсом

Вариант: **Notification**.

## Что дано

Предметные объекты, внешний API и вспомогательные типы уже подготовлены. В `app/domain/senders.py` даны заготовки общего интерфейса и двух исполнителей. Их поведение и основной метод `NotificationService.send()` требуется завершить самостоятельно. Сигнатуры сохранены; новые слои и выбор архитектуры не нужны.

## Задание

### Шаг 1. Реализуйте общий интерфейс и два поведения

Оформите `NotificationSender` как абстрактный класс с `send(notification) -> DeliveryReceipt`. Перенесите поведение каналов в `EmailSender` и `SmsSender`.

Каждый отправитель проверяет свой контакт готовой `contact()` и возвращает квитанцию с каналом, адресатом и исходным текстом. Сам отправитель не пишет в `Outbox`.

Сервис выбирает объект из отображения и одинаково вызывает `send()`. Создание отображения пока может оставаться в `__init__`; определять алгоритм по конкретному типу отправителя не нужно.

### Шаг 2. Соберите путь вызова в `NotificationService.send()`

Выберите отправителя по каналу, вызовите `send()` один раз, проверьте квитанцию через `validate_receipt()` и только затем добавьте её в `Outbox`. Неизвестный канал — `UNSUPPORTED_CHANNEL`. Не выбирайте алгоритм по конкретному классу исполнителя.

### Шаг 3. Проверьте повторное использование

Тем же отправителем обработайте сообщения «FIRST», сообщение без нужного контакта и «THIRD». Первый и третий результаты независимы; в журнале только две успешные отправки.

## Примеры и границы

- Одно сообщение даёт квитанции `EMAIL/email` и `SMS/phone` одного типа.
- Нет нужного контакта — `MISSING_CONTACT`.
- Методы возвращают `DeliveryReceipt`, не `None` и не печать вместо результата.
- Абстрактный отправитель без реализации метода не используется.

Последовательности и конфигурации дополнительно проверяются в `tests/test_progression.py`. Прочитайте ожидаемый результат каждого сценария до реализации.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
Описание объектов — в [REFERENCE.md](REFERENCE.md), исходные результаты тестов — в [STARTER-STATE.md](STARTER-STATE.md).
